Contingut

Criteri general

  • S’ha d’evitar emprar conceptes, termes, etc. que encara no s’han introduït al cos del text. Si es fa, cal referenciar la secció o el callout on s’explica el concepte en detall.
  • No s’ha de repetir informació (Don’t Repeat Yourself, DRY): ús de referències creuades; per a recordatoris puntuals, {.callout-caution}.
  • Mnemònics: El primer cop, si no estan prop d’una taula on se n’indiqui l’expansió, han d’anar seguits de l’expansió entre parèntesis. Ex: addi (add immediate).
  • No es permet que un nivell de profunditat tingui un sol ítem. En aquest cas, s’ha de pujar el contingut un nivell.
  • L’arquitectura de referència és RISC-V. No s’ha de fer cap referència a MIPS (tret d’on ja s’ha fet explícitament).

Fitxer de referència tècnica (11_riscv.qmd) i directori 21_riscv/

El fitxer 11_riscv.qmd és el compendi de referència tècnica de l’assignatura (capítol «Referència tècnica» del llibre). Conté exclusivament callouts #nte-rv-* sense text narratiu entre ells. Totes les taules s’obtenen via {{< include 21_riscv/NOM.qmd >}} (rutes relatives a l’arrel del projecte, sense ../).

El directori 21_riscv/ conté els fragments de taula reutilitzables (sols les files, sense header ni caption). Cada fitxer es pot incloure a múltiples llocs: als Ax.qmd dins el callout temàtic corresponent, i a 11_riscv.qmd per agrupar continguts de diverses extensions o categories sota un sol header diferent.

Convencions dels fitxers 21_riscv/:

  • Només files de taula (sense header, sense caption, sense atributs {}).
  • Nom: <extensió>_<categoria>_<descripció>.qmd. Exemples: RV32I_instruccions_aritmetiques.qmd, Zicsr_instruccions.qmd, RARS_syscall_codis.qmd.
  • Excepció: els callouts que contenen figures SVG (#fig-) no s’externalitzen; es reprodueixen íntegrament a 11_riscv.qmd amb IDs #nte-rv-* i #fig-rv-* per evitar IDs duplicats amb T2/T5/T9.

IDs dels callouts a 11_riscv.qmd: prefix #nte-rv- (en comptes del #nte- dels Ax.qmd), per evitar conflictes de ID Quarto. Les figures dins 11_riscv.qmd usen #fig-rv-*.

Referències creuades cap als Apunts: cada callout de 11_riscv.qmd acaba amb una nota «Vegeu @X[, @Y] i @Z.» que apunta al callout (o callouts) del Ax.qmd on es presenta el contingut per primer cop, amb el mateix format que les referències dels enunciats (§Problemari i solucionari (PE/PS)). Quan un mateix contingut es presenta a més d’un Ax.qmd (p. ex. mv/not/neg a T2/T3/T4), es llisten totes les referències. Els callouts sense cap presentació a la teoria (material exclusiu del compendi, com les directives RARS) no en porten.

Taules amb més d’un fragment font: Quarto no permet encadenar dos {{< include >}} consecutius dins la mateixa taula pipe — el primer tanca la taula i la resta cau a text cru (line block de Pandoc). Quan una taula de 11_riscv.qmd combina files de més d’un fitxer de 21_riscv/ (p. ex. aritmètica + lui sota un sol header), els fragments es fusionen prèviament en un únic fitxer generat per 25_scripts/gen_taules_auto.py (manifest: 24_specs/taules_fusio.toml) i 11_riscv.qmd hi fa un únic {{< include auto_riscv/NOM.qmd >}}. El directori auto_riscv/ és generat (gitignored); no s’edita a mà.

A diferència dels altres scripts de 25_scripts/, aquest no es crida des del pre-render de _quarto.yml: Quarto resol els {{< include >}} dels capítols en un escaneig de configuració que s’executa abans del pre-render, de manera que el fitxer fusionat ha d’existir al disc abans d’invocar quarto. Cal executar-lo manualment (vegeu README.md) el primer cop, i sempre que s’editi un fitxer de 21_riscv/ que aparegui a 24_specs/taules_fusio.toml (si no, auto_riscv/ queda desactualitzat en silenci: quarto render no fallarà, però la taula final no reflectirà el canvi). Els fitxers font de 21_riscv/ continuen sent l’única font de veritat.

Contingut d’Aprofundiment exclòs de 11_riscv.qmd: el compendi de referència tècnica no pot incloure contingut que provingui únicament d’un callout d’Aprofundiment d’un Ax.qmd (material opcional, no bàsic). Exemple: Zicsr_instruccions_immediats.qmd (csrrwi/csrrsi/csrrci) es presenta a A9.qmd dins un callout d’Aprofundiment; per això 11_riscv.qmd només inclou Zicsr_instruccions.qmd (les instruccions base), no la taula d’immediats. El fitxer de 21_riscv/ es manté igualment, per a l’ús des del Ax.qmd corresponent.

Decisions per tema

T2 i T3

  • .globl vs. .global: s’usa .globl (forma estàndard de GNU AS); .global és un àlies acceptat però no s’usa als exemples ni al laboratori.
  • Mode base + desplaçament (terme canònic a EC): el mode d’adreçament que usa la sintaxi offset(rs1) s’anomena mode base + desplaçament a EC. El terme mode memòria és un sinònim de la literatura; es menciona com a tal al callout {#cau-mode-base-desplacament} de T2, però no s’usa com a terme principal.
  • Modes d’adreçament: quatre modes a EC: registre, immediat, base+desplaçament, relatiu al PC. lui → immediat; jalr → base+desplaçament.
  • Terminologia de salts: relatiu al PC (beq, jal) vs. indirecte (jalr). Tots els salts condicionals de RV32I són relatius al PC.
  • Etiquetes de bucle: bucle: i fibucle: als exemples didàctics; en la pràctica s’admeten etiquetes descriptives (while:, fiwhile:, etc.).
  • Registres als exemples: t0, t1, t2… tant en C com en assemblador per eliminar el soroll del mapatge.
  • la label+offset: admès a EC (pissarra i exàmens) però no suportat per RARS; al laboratori cal la + addi.
  • Optimitzacions de bucle: les tres optimitzacions numerades es defineixen a T4 (§4.5); el prerequisit no numerat (extracció d’invariants) s’introdueix a T2 (Extracció d’invariants) i s’hi remet des de T4. La numeració és única per al bloc, no es reparteix entre temes, i és: #1 accés seqüencial, #2 avaluació de la condició al final, #3 eliminació de la variable d’inducció (vegeu §T4 a continuació).
  • Pseudoinstruccions vs. macros: distinció explícita establerta a T3. Les macros es defineixen amb .macro/.end_macro i són locals al programa.
  • Alineació de la pila: la mida del BA i el valor de sp han de ser múltiples de 4 bytes a EC (relaxació pedagògica). L’ABI estàndard de RV32I exigeix múltiples de 16 bytes; aquest fet es menciona explícitament a {#nte-abi-alineacio-pila} de T3.
  • Retorn de resultats: les subrutines retornen com a màxim dos resultats escalars, per a0 i a1. El segon (a1) s’usa habitualment per a un codi d’error o un segon valor de retorn. Documentat a {#nte-abi-pas-parametres} de T3.
  • Retorn de subrutines — ret: als exemples s’usa sempre ret (pseudoinstrucció estàndard, més llegible), no jalr x0, 0(ra).
  • Format d’adreces de memòria: sense espais (0x10010000), no amb separador cada 4 nibbles.
  • .section: no s’utilitza. Només .data i .text, sense indentar, a columna 0 (vegeu també §Convencions globals del laboratori).

T4

  • Prerequisit implícit (no numerat): Extracció d’invariants.
  • Optimització #1: Accés seqüencial.
  • Optimització #2: Avaluació de la condició al final.
  • Optimització #3: Eliminació de la variable d’inducció.

T1 i T5

  • «En excés» / «codificació en excés»: terme correcte per al concepte general de representació d’enters (T1, @sec-enters-en-exces). Usat quan el valor K és arbitrari.
  • «Esbiaixat» / «biaix»: terme correcte per a l’exponent IEEE 754 específicament (T5, L5, S5). Font: Viquipèdia cat., «Format de coma flotant de precisió simple». No és sinònim de «biaix estadístic» (context RNE): són homònims, no el mateix concepte.
  • «Mantissa» (no «significand»): terme preferent a EC per a la part \(1{,}F\) del nombre en coma flotant. L’estàndard IEEE 754 en anglès prefereix formalment significand perquè mantissa ja té un significat establert en el context de logaritmes (Knuth en critica l’ús aquí per aquest motiu), però aquesta distinció és interna a l’anglès tècnic: cap font normativa catalana la reflecteix. Termcat (Cercaterm) només té fitxa per a «mantissa» (àmbit Matemàtiques, logaritmes); la Viquipèdia catalana, tant a «Format de coma flotant de precisió simple» com a «Format de coma flotant Bfloat16», usa «mantissa» com a terme principal («significand» hi apareix només com a manlleu anglès puntual, no com a alternativa establerta). A EC, l’ambigüitat que criticava Knuth ja queda resolta amb la distinció pròpia del projecte entre fracció (\(F\), els bits emmagatzemats) i mantissa (\(1{,}F\), amb el bit ocult): vegeu més amunt. Es descarta, doncs, l’adopció de «significand».

T5

  • quartet (no nibble): terme preferit per als grups de 4 bits.
  • Fracció vs. mantissa: en el context IEEE 754, F designa la fracció (els 23/10 bits emmagatzemats); la mantissa és 1.F (inclou el bit ocult). Usar-los amb precisió evita confusions al calcular rangs i errors de representació.
  • Posició menys significativa (no posició 0): per referir-se al darrer bit de la fracció, a fi d’evitar l’ambigüitat entre indexació des de 0 o des del LSB.
  • Blocs de codi .default: per als càlculs pas a pas IEEE 754 (descomposició S/Eu/F, sumes binàries, alineació), es fa servir {.default filename="..."} amb el nom del pas com a etiqueta (filename="ft2 = 0x417AC000").
  • Solucionari (PS): estructura de cada solució: **Enunciat:** @exr-... → explicació → blocs de càlcul → resultat en $$\boxed{...}$$. Els resultats intermedis van en blocs .default; el codi RISC-V en blocs .s filename="RV32IF".
  • fcvt.w.s/fcvt.wu.s s’arrodoneixen segons el camp rm de la instrucció, no trunquen sempre. Sense operand de mode (fcvt.w.s rd, rs1), l’assemblador RISC-V hi assigna dyn (mode dinàmic: el del registre frm, RNE per defecte a RARS). Per traduir el cast (int) de C (que trunca cap a zero) cal escriure explícitament fcvt.w.s rd, rs1, rtz.
  • flt.s rd, rs1, rs2 avalua \(rs1 < rs2\). Per implementar a > b cal invertir els operands (flt.s rd, b, a), no negar el resultat.
  • No associativitat (half): exemple canònic: \(A = \texttt{0xF3FD}\), \(B = \texttt{0x73FD}\), \(C = \texttt{0x3C00}\) → \((A+B)+C = 1 \neq 0 = A+(B+C)\).

T6

  • Ordre de seccions: Rendiment → Llei d’Amdahl → Potència, tant a la teoria com als enunciats i les solucions. El nom de la secció de potència és «Potència» (no «Potència i consum»).
  • Notació: les definicions formals (teoria) usen les formes llargues \(t_{clock}\), \(f_{clock}\), \(n_{ins}\); a partir de la seva introducció, la resta del tema (exemples, enunciats, solucions) usa lliurement les abreviatures \(t_c\), \(f\), \(N\).
  • «Capacitat equivalent» (terme principal) / «capacitància» (sinònim): per a \(C\) a les fórmules de potència dinàmica. S’introdueix «capacitat equivalent» amb «(capacitància)» entre parèntesis a la primera aparició de cada fitxer; les aparicions posteriors poden fer servir qualsevol dels dos termes indistintament. Es descarta «càrrega capacitiva» (calc directe de l’anglès capacitive load, no normatiu).
  • Sigles CMOS i CF: s’expandeixen a la primera aparició del cos de cada fitxer («complementary metal–oxide–semiconductor (CMOS)»; «instruccions de coma flotant (CF)») i tenen entrada a 12_sigles_simbols.qmd. FPU no s’usa als enunciats ni les solucions: es prefereix «unitat de coma flotant» (o «unitat CF» en segones aparicions).
  • Guany / speedup: el terme principal a EC és «guany»; speedup n’és el manlleu anglès i s’escriu en cursiva només a la primera aparició de cada fitxer.
  • Majúscules de lleis i principis: «llei d’Amdahl», «llei de Moore» i «escalat de Dennard» s’escriuen amb minúscula inicial al cos del text (com qualsevol altre terme comú), tret dels títols de secció o de callout, que segueixen la regla general de majúscula de frase (p. ex. ## Llei d'Amdahl).
  • \(I_{fuita}\) (no I_leak) i «corrents de fuita» (plural, com a fenomen general): notació i terme establerts a T6, reutilitzats a T7 i T8.
  • Etiquetes de classe d’instruccions a les taules d’exercicis («Load», «Store», «Branch», «L/S»…): es mantenen en anglès com a etiquetes de columna/fila (no com a prosa); pendent una decisió transversal sobre si convertir-les a «Lectura/Escriptura/Salt» (vegeu TODO.md §T6).
  • Amplada de les figures extretes de PDF (svg.md §15): l’atribut width de la imatge SVG es normalitza a 100%; l’amplada visual final la determina exclusivament l’atribut {width="X%"} del bloc Quarto, amb el mateix valor a HTML i a PDF (sense divergència entre formats). A T6: 40% per a fig-amdahl i fig-tc-tc-prima; 50% per a les tres figures fig-not-*.

T7

  • \(t_{bloc}\) (no \(t_{block}\)): notació canònica per al temps de transferència d’un bloc entre la MC i la memòria principal (teoria, enunciats i solucions).
  • «línia» vs. «bloc»: la línia és el contenidor de la MC; el bloc és el contingut (fragment de la memòria principal). Els enunciats especifiquen la geometria com a «\(N\) línies amb blocs de \(B\) bytes» o «\(N\) vies per conjunt», mai «\(N\) blocs» per comptar línies o vies.
  • Notació multinivell: la dels subíndexs de nivell de la teoria (@eq-tam-multinivell): \(t_{h_{L1}}\), \(t_{h_{L2}}\), \(m_{L1}\), \(m_{L2}\); els subíndexs numèrics (\(m_1\), \(m_2\)…) es reserven per enumerar alternatives dins d’un mateix exercici.
  • Unitats de capacitat (criteri transversal): unitats binàries (KiB, MiB, GiB) per a registres, memòries cau i memòria principal; unitats decimals (GB, TB) per a l’emmagatzematge secundari, els costos ($/GB) i les amplades de banda (GB/s, TB/s).

T8

  • Precedència textual (criteri general, aplicat aquí al bit E): els apunts (Ax.qmd) prevalen sobre els problemes (Ex.qmd) i solucions (Sx.qmd); dins dels apunts, el cos del text i els .callout-note prevalen sobre la resta de callouts i continguts.
  • Bit de permís d’escriptura E: la teoria i els enunciats/solucions usen el bit E (E = 1 → permís d’escriptura; E = 0 → només lectura), no W. Quan un enunciat heretat usava W (1 = només lectura, polaritat oposada), s’ha reescrit a E, aplicant el criteri de precedència textual.
  • Bit de validesa V: la teoria usa V (valid bit, notació RISC-V Sv32 / Harris & Harris) per al bit de presència d’una PTE, no P. Els enunciats i solucions, que usaven P (notació x86 i dels exàmens antics d’EC), s’han reescrit a V, aplicant el mateix criteri de precedència textual; #wrn-mv-notacio-v a A8.qmd documenta la notació P per a qui consulti exàmens anteriors.
  • Mida de pàgina explícita: si un enunciat de memòria virtual no especifica la mida de pàgina però les adreces la impliquen, s’afegeix explícitament a l’enunciat (rigor i bona definició).
  • Estat inicial del TLB: quan es dona l’estat inicial d’un TLB completament associatiu amb LRU, cal especificar també l’ordre d’ús (MRU→LRU) de les entrades vàlides; sense això el reemplaçament és ambigu.
  • Canvi de mida de pàgina sobre un estat fix: una pregunta que reutilitzi una taula de pàgines o un TLB donats per a una mida de pàgina concreta i en canviï la mida es torna incoherent; en aquests casos es reformula en clau qualitativa (efecte sobre el nombre de fallades).

T9

  • ecall: la convenció de crides al sistema Linux/RISC-V usa a7 per al codi de servei (no a0) i admet fins a sis arguments (a0–a5).
  • RSE: cal salvar tots els registres generals sense excepció, independentment de les convencions de l’ABI.
  • mepc: en excepcions, apunta a la instrucció causant; en interrupcions, a la instrucció següent. L’ajust (mepc + 4) és responsabilitat de la RSE, no del hardware.
  • Zicsr: les instruccions CSR (csrrw, csrrs, csrrc i variants immediates) pertanyen a l’extensió Zicsr, no a RV32I base. Els callouts d’ISA s’etiqueten ## Zicsr ISA — ....
  • Mode S: el tractament de fallades de TLB per programari requereix mode S (satp, stval, sfence.vma). El cos del text descriu el mecanisme en mode M; l’aprofundiment cobreix mode S.

Problemari i solucionari (PE/PS)

  • Referències creuades cap a la teoria (Nivell 2): als exercicis i solucions, afegir referències @sec-nom a la secció de teoria rellevant quan el concepte clau no és obvi o quan l’estudiant típicament s’encalla. No de forma mecànica a tots els exercicis, sinó selectivament. Nivell 3 (@nte-, @tip-…) admès quan la solució és aplicació directa d’un exemple concret de teoria.
    • Format recomanat als enunciats: nota al final del bloc {#exr-} o sota la capçalera de secció: «Vegeu @sec-nom.»
    • Format recomanat a les solucions: integrat al text de la solució on es fa servir el concepte.
  • Cobertura: aplicar als xats de revisió de cada tema. E2/S2 es retoquen en un xat breu un cop A2.qmd tingui els slugs complets (tasca Claude Code).
  • Veu dels enunciats: 2a persona del plural («Traduïu», «Calculeu», «Contesteu»; no «Tradueix», «Calcula», «Contesta»). Aplicat sistemàticament a E6 i E4.

Convencions globals del laboratori

  • Punt d’entrada: _start (no main). Directiva .globl _start al principi del fitxer.
  • _start ha de ser la primera etiqueta de .text: RARS inicia l’execució a la primera instrucció del segment de text, i l’opció «start at main» només reconeix l’etiqueta main. _start no ha de tenir pròleg ni epíleg, perquè no és callee de ningú i acaba amb la sortida li a7, 93 + ecall; sí que ha d’usar registres segurs per a les dades pròpies que travessen crides. Aplicat a L4, L5 i L6, verificat empíricament amb RARS 1.6; pendent d’aplicar a L3.
  • Sortida del programa: li a7, 93 + ecall (syscall exit2). No es fa servir startup.s.
  • Directives de segment: .data i .text (sense .section), sense indentar, a columna 0.
  • Codi dels exercicis: integrat al .qmd (no hi ha fitxers .s separats). Els alumnes fan copy-paste.
  • Estructura de cada exercici: enunciat en {#exr-...} + solució en {#sol-...}.
  • Lliuraments i Lectura prèvia: dues seccions fixes al principi de cada sessió, en aquest ordre. “Lliuraments” porta una taula amb els exercicis i el nom del fitxer de lliurament; “Lectura prèvia” porta una taula amb columnes “Concepte” i “On trobar-ho”.

Llenguatge

Referència normativa

  • La norma general és l’IEC (Institut d’Estudis Catalans): DIEC2 i Optimot.
  • El català normatiu és el criteri de resolució per a qualsevol dubte lèxic o ortogràfic no cobert explícitament per aquesta guia.

Criteris generals

  • Camel Case:
    • Només en els sintagmes anglesos.
    • En els sintagmes catalans (títols inclosos) només la primera lletra en majúscula.
  • Després de dos punts: minúscula en enumeracions i explicacions breus; majúscula en citacions textuals i paràgrafs independents.
  • Nombres:
    • Les quantitats petites (una instrucció, dos bytes) o genèriques (mil, deu mil) al cos del text preferiblement amb lletres.
    • La resta en nombres: “5 V”, “8 bits”, “12 bits”, “16 bits”, “32 bits”, “RV32I”, x0-x31.
    • Separador de milers: espai («65 535»), no coma anglesa («65,535», ambigua amb la coma decimal catalana) ni punt.
  • Prefixos de mida binaris vs. decimals: KiB, MiB, GiB, TiB (IEC, base 2) per a qualsevol mida que sigui una potència de 2 —mida de cau, de memòria, de pàgina, de bloc, rangs d’adreçament, etc.—, que és la immensa majoria de casos a EC. KB, MB, GB, TB (base 10) es reserven exclusivament per a mides genuïnament decimals (p. ex. la capacitat comercial anunciada d’un disc, o les referències de mercat aproximades de A7.qmd §El problema de la diferència entre processador i memòria, El problema de la diferència (gap) entre processador i memòria). Explicat a A2.qmd (Essencial 2.5), primera aparició al llibre; en cas de dubte, per defecte KiB/MiB/GiB/TiB.
  • Dígits hexadecimals, majúscules vs. minúscules: la preferència és per majúscules (p. ex. 0xE6666666), però s’admeten minúscules perquè és el criteri de RARS. No cal, doncs, unificar-ho sistemàticament allà on ja apareguin totes dues grafies.
  • Veu impersonal: Sempre: “Cal verificar que no hi ha errors” (no “hem de verificar”). Excepcions:
    • {.callout-tip}: segona persona del singular per a instruccions directes a l’estudiant (calcula, determina, suposa que…). Criteri revisat el 2026-07 (revisió interna T2, xat A2-E2-S2); no confondre amb els enunciats #exr-, que usen plural (vegeu §Problemari i solucionari). Excepció dins la pròpia excepció: als exemples narrats (una traça o un escenari que es va desenvolupant pas a pas, no una instrucció puntual), s’admet el «nosaltres» expositiu (Considerem un sistema amb…, Suposem que…, Sabem que…): pràctica consolidada a T7 i T8, revisada el 2026-07 (revisió interna T8, xat A8-E8-S8). El criteri per triar entre tots dos: si la frase estableix el marc o l’estat d’un exemple, «nosaltres»; si demana una acció puntual a l’estudiant («calcula», «indica»), 2a persona del singular.
    • Instruccions operatives pas a pas: imperatiu en segona persona del plural (descarregueu, obriu, executeu).

Puntuació

  • Punt d’acabament de frase: Sempre. Totes les frases del cos del text, incloses les llistes de vinyetes, han d’acabar obligatòriament en punt. Excepció: les llistes de passos en notació tècnica amb fletxa (→) no porten punt final, ja que no constitueixen prosa sinó notació de seguiment pas a pas.
  • Negretes acabades en dos punts: Els dos punts mai en negreta.
  • Nombres decimals: Amb coma, no amb punt. Ex: «0,5 V», «3,14», \(1{,}045\).
  • Abreviatura de versus: S’usa vs. (amb punt), que és la forma correcta en català segons l’Optimot. No s’usa «versus» desenvolupat excepte en prosa formal.

Ressaltat conceptual (negretes)

  • Conceptes nuclears: Paraules que defineixen l’essència de la secció (ex: abstracció, ISA).
  • Components del sistema: Elements de l’arquitectura (ex: registres, unitat de control).
  • Atributs clau: Paraules que marquen diferències operatives (ex: màxim rendiment, més lenta).
  • Sigles i acrònims: En la seva definició i aparicions clau.
  • Referències a objectes: (ex: “Tal com mostra la Figura 1.2”).

Negretes dins de callouts:

  • Als callouts curts i sense títol per defecte (#cau- Essencial, #imp- Criteri EC), la negreta marca el nucli del recordatori o criteri (coherent amb la taula de callouts de §Callouts; vegeu-hi l’excepció per a callouts llargs).
  • Als callouts llargs (#tip- Exemple, #nte- RISC-V, #wrn- Aprofundiment), s’aplica el mateix criteri de ressaltat conceptual que al cos del text.

Anglicismes i terminologia obligatòria

  • Primera aparició: Traducció al català seguida de l’anglicisme en cursiva i entre parèntesis. Exemple: biblioteques de funcions (libraries).
  • Aparicions posteriors: Es pot utilitzar l’anglicisme directament, sempre sense cursiva.
  • Triples asteriscs (***): S’utilitzen exclusivament quan el terme és un anglicisme en la seva primera aparició i alhora és un concepte nuclear que requereix negreta. Exemple: **maquinari** (***hardware***).

Codi, matemàtiques i cursiva

Regla general: el format el determina la naturalesa de l’element, no el context on apareix.

  • Backtick (`) — codi: tot allò que existeix literalment en un programa, en una ISA o en un fitxer: registres (t0; també els CSR: mepc, mstatus…, fins i tot en títols de secció, com fa T9), instruccions (addi), directives (.data), variables i expressions C (i, p++), camps de bits (opcode), adreces concretes (0x10010000), fitxers, comandes i etiquetes.
  • LaTeX math ($…$) — matemàtiques: quantitats, variables i expressions matemàtiques: mides genèriques (\(n\) bits, \(B = 2^b\)), índexs de fórmules i algorismes (\(q_i\)), rangs (\([-2^{11}, 2^{11}-1]\)), operacions (\(rd = M_w[rs1 + SignExt(offset)]\)). Els superíndexs numèrics s’escriuen sempre en math ($2^{8}$), també dins de cel·les de taula; no s’usa la sintaxi Pandoc 2^8^.
  • Cursiva — llengua: anglicismes en primera aparició (vegeu §Anglicismes) i èmfasi lleu. Mai per a codi ni per a variables matemàtiques.
  • Text pla — la resta: nombres amb unitats («8 bits», «4 bytes»), noms d’arquitectures i extensions (RISC-V, RV32I, extensió M), tipus de format d’instrucció (S, B).

Cas fronterer — variables d’una lletra: si l’element viu en un programa concret (està declarat al codi de l’exemple), backtick (i, p); si viu en una fórmula o algorisme abstracte, math (\(i\), \(n-1\)).

Dins de les fórmules:

  • \text{…}: paraules catalanes, sigles i unitats (\(\text{CPI}\), \(t_h = 2\text{ ns}\), \(\text{núm. encerts}\)). És l’opció per defecte per a qualsevol camp o paraula (\(\text{offset}\), \(\text{índex}\)).
  • \texttt{…}: literals de codi dins d’una fórmula (\(\texttt{0x100100F}\), \(\texttt{vec[i]}\)).

### Extensions RISC-V a EC

A EC s'estudien les extensions següents:

| Extensió | Descripció | Tema |
| :--- | :--- | :--- |
| RV32I | Base entera | Tots |
| M | Multiplicació i divisió entera | T4 |
| F | Coma flotant | T5 |
| Zicsr | Registres de control i estat | T9 |
| Zifencei | Instruccions de barrera d'instruccions (`fence.i`) | T9 |

El camp `filename` dels blocs de codi reflecteix les extensions actives: `RV32I`, `RV32IM`, `RV32IF`, `RV32IZicsr`, `RV32IZicsrZifencei`.

### Decisions per tema

#### T2 i T3

- **`.globl` vs. `.global`**: s'usa `.globl` (forma estàndard de GNU AS); `.global` és un àlies acceptat però no s'usa als exemples ni al laboratori.
- **Mode base + desplaçament** (terme canònic a EC): el mode d'adreçament que usa la sintaxi `offset(rs1)` s'anomena **mode base + desplaçament** a EC. El terme **mode memòria** és un sinònim de la literatura; es menciona com a tal al callout `{#cau-mode-base-desplacament}` de T2, però no s'usa com a terme principal.
- **Modes d'adreçament**: quatre modes a EC: registre, immediat, base+desplaçament, relatiu al PC. `lui` → immediat; `jalr` → base+desplaçament.
- **Terminologia de salts**: relatiu al PC (`beq`, `jal`) vs. indirecte (`jalr`). Tots els salts condicionals de RV32I són relatius al PC.
- **Etiquetes de bucle**: `bucle:` i `fibucle:` als exemples didàctics; en la pràctica s'admeten etiquetes descriptives (`while:`, `fiwhile:`, etc.).
- **Registres als exemples**: `t0`, `t1`, `t2`... tant en C com en assemblador per eliminar el soroll del mapatge.
- **`la label+offset`**: admès a EC (pissarra i exàmens) però no suportat per RARS; al laboratori cal `la` + `addi`.
- **Optimitzacions de bucle**: les tres optimitzacions numerades es defineixen a T4 (§4.5); el prerequisit no numerat (extracció d'invariants) s'introdueix a T2 (@sec-extraccio-invariants) i s'hi remet des de T4. La numeració és única per al bloc, no es reparteix entre temes, i és: #1 accés seqüencial, #2 avaluació de la condició al final, #3 eliminació de la variable d'inducció (vegeu §T4 a continuació).
- **Pseudoinstruccions vs. macros**: distinció explícita establerta a T3. Les macros es defineixen amb `.macro`/`.end_macro` i són locals al programa.
- **Alineació de la pila**: la mida del BA i el valor de `sp` han de ser **múltiples de 4 bytes** a EC (relaxació pedagògica). L'ABI estàndard de RV32I exigeix múltiples de 16 bytes; aquest fet es menciona explícitament a `{#nte-abi-alineacio-pila}` de T3.
- **Retorn de resultats**: les subrutines retornen com a màxim dos resultats escalars, per `a0` i `a1`. El segon (`a1`) s'usa habitualment per a un codi d'error o un segon valor de retorn. Documentat a `{#nte-abi-pas-parametres}` de T3.
- **Retorn de subrutines — `ret`**: als exemples s'usa sempre `ret` (pseudoinstrucció estàndard, més llegible), no `jalr x0, 0(ra)`.
- **Format d'adreces de memòria**: sense espais (`0x10010000`), no amb separador cada 4 nibbles.
- **`.section`**: no s'utilitza. Només `.data` i `.text`, sense indentar, a columna 0 (vegeu també §Convencions globals del laboratori).

#### T4

- Prerequisit implícit (no numerat): **Extracció d'invariants**.
- **Optimització #1**: Accés seqüencial.
- **Optimització #2**: Avaluació de la condició al final.
- **Optimització #3**: Eliminació de la variable d'inducció.

#### T1 i T5

- **«En excés» / «codificació en excés»**: terme correcte per al concepte general de representació d'enters (T1, `@sec-enters-en-exces`). Usat quan el valor K és arbitrari.
- **«Esbiaixat» / «biaix»**: terme correcte per a l'exponent IEEE 754 específicament (T5, L5, S5). Font: Viquipèdia cat., «Format de coma flotant de precisió simple». *No* és sinònim de «biaix estadístic» (context RNE): són homònims, no el mateix concepte.
- **«Mantissa» (no «significand»)**: terme preferent a EC per a la part $1{,}F$ del nombre en coma flotant. L'estàndard IEEE 754 en anglès prefereix formalment *significand* perquè *mantissa* ja té un significat establert en el context de logaritmes (Knuth en critica l'ús aquí per aquest motiu), però aquesta distinció és interna a l'anglès tècnic: **cap font normativa catalana la reflecteix**. Termcat (Cercaterm) només té fitxa per a «mantissa» (àmbit Matemàtiques, logaritmes); la Viquipèdia catalana, tant a «Format de coma flotant de precisió simple» com a «Format de coma flotant Bfloat16», usa «mantissa» com a terme principal («significand» hi apareix només com a manlleu anglès puntual, no com a alternativa establerta). A EC, l'ambigüitat que criticava Knuth ja queda resolta amb la distinció pròpia del projecte entre **fracció** ($F$, els bits emmagatzemats) i **mantissa** ($1{,}F$, amb el bit ocult): vegeu més amunt. Es descarta, doncs, l'adopció de «significand».

#### T5

- **`quartet`** (no `nibble`): terme preferit per als grups de 4 bits.
- **Fracció** vs. **mantissa**: en el context IEEE 754, `F` designa la fracció (els 23/10 bits emmagatzemats); la **mantissa** és `1.F` (inclou el bit ocult). Usar-los amb precisió evita confusions al calcular rangs i errors de representació.
- **Posició menys significativa** (no `posició 0`): per referir-se al darrer bit de la fracció, a fi d'evitar l'ambigüitat entre indexació des de 0 o des del LSB.
- **Blocs de codi `.default`**: per als càlculs pas a pas IEEE 754 (descomposició S/Eu/F, sumes binàries, alineació), es fa servir `{.default filename="..."}` amb el nom del pas com a etiqueta (`filename="ft2 = 0x417AC000"`).
- **Solucionari (PS)**: estructura de cada solució: `**Enunciat:** @exr-...` → explicació → blocs de càlcul → resultat en `$$\boxed{...}$$`. Els resultats intermedis van en blocs `.default`; el codi RISC-V en blocs `.s filename="RV32IF"`.
- **`fcvt.w.s`/`fcvt.wu.s` s'arrodoneixen segons el camp `rm`** de la instrucció, no trunquen sempre. Sense operand de mode (`fcvt.w.s rd, rs1`), l'assemblador RISC-V hi assigna `dyn` (mode dinàmic: el del registre `frm`, RNE per defecte a RARS). Per traduir el *cast* `(int)` de C (que trunca cap a zero) cal escriure explícitament `fcvt.w.s rd, rs1, rtz`.
- **`flt.s rd, rs1, rs2`** avalua $rs1 < rs2$. Per implementar `a > b` cal invertir els operands (`flt.s rd, b, a`), no negar el resultat.
- **No associativitat** (*half*): exemple canònic: $A = \texttt{0xF3FD}$, $B = \texttt{0x73FD}$, $C = \texttt{0x3C00}$ → $(A+B)+C = 1 \neq 0 = A+(B+C)$.

#### T6

- **Ordre de seccions**: Rendiment → Llei d'Amdahl → Potència, tant a la teoria com als enunciats i les solucions. El nom de la secció de potència és **«Potència»** (no «Potència i consum»).
- **Notació**: les definicions formals (teoria) usen les formes llargues $t_{clock}$, $f_{clock}$, $n_{ins}$; a partir de la seva introducció, la resta del tema (exemples, enunciats, solucions) usa lliurement les abreviatures $t_c$, $f$, $N$.
- **«Capacitat equivalent» (terme principal) / «capacitància» (sinònim)**: per a $C$ a les fórmules de potència dinàmica. S'introdueix «capacitat equivalent» amb «(capacitància)» entre parèntesis a la primera aparició de cada fitxer; les aparicions posteriors poden fer servir qualsevol dels dos termes indistintament. Es descarta «càrrega capacitiva» (calc directe de l'anglès *capacitive load*, no normatiu).
- **Sigles CMOS i CF**: s'expandeixen a la primera aparició del cos de cada fitxer («*complementary metal–oxide–semiconductor* (CMOS)»; «instruccions de coma flotant (CF)») i tenen entrada a `12_sigles_simbols.qmd`. **FPU** no s'usa als enunciats ni les solucions: es prefereix «unitat de coma flotant» (o «unitat CF» en segones aparicions).
- **Guany / *speedup***: el terme principal a EC és **«guany»**; *speedup* n'és el manlleu anglès i s'escriu en cursiva només a la primera aparició de cada fitxer.
- **Majúscules de lleis i principis**: «llei d'Amdahl», «llei de Moore» i «escalat de Dennard» s'escriuen amb minúscula inicial al cos del text (com qualsevol altre terme comú), tret dels títols de secció o de callout, que segueixen la regla general de majúscula de frase (p. ex. `## Llei d'Amdahl`).
- **$I_{fuita}$** (no `I_leak`) i **«corrents de fuita»** (plural, com a fenomen general): notació i terme establerts a T6, reutilitzats a T7 i T8.
- **Etiquetes de classe d'instruccions a les taules d'exercicis** («Load», «Store», «Branch», «L/S»…): es mantenen en anglès com a etiquetes de columna/fila (no com a prosa); pendent una decisió transversal sobre si convertir-les a «Lectura/Escriptura/Salt» (vegeu `TODO.md §T6`).
- **Amplada de les figures extretes de PDF** (`svg.md §15`): l'atribut `width` de la imatge SVG es normalitza a `100%`; l'amplada visual final la determina exclusivament l'atribut `{width="X%"}` del bloc Quarto, amb el mateix valor a HTML i a PDF (sense divergència entre formats). A T6: `40%` per a `fig-amdahl` i `fig-tc-tc-prima`; `50%` per a les tres figures `fig-not-*`.

#### T7

- **$t_{bloc}$ (no $t_{block}$)**: notació canònica per al temps de transferència d'un bloc entre la MC i la memòria principal (teoria, enunciats i solucions).
- **«línia» vs. «bloc»**: la **línia** és el contenidor de la MC; el **bloc** és el contingut (fragment de la memòria principal). Els enunciats especifiquen la geometria com a «$N$ línies amb blocs de $B$ bytes» o «$N$ vies per conjunt», mai «$N$ blocs» per comptar línies o vies.
- **Notació multinivell**: la dels subíndexs de nivell de la teoria (`@eq-tam-multinivell`): $t_{h_{L1}}$, $t_{h_{L2}}$, $m_{L1}$, $m_{L2}$; els subíndexs numèrics ($m_1$, $m_2$…) es reserven per enumerar alternatives dins d'un mateix exercici.
- **Unitats de capacitat** (criteri transversal): unitats binàries (KiB, MiB, GiB) per a registres, memòries cau i memòria principal; unitats decimals (GB, TB) per a l'emmagatzematge secundari, els costos ($/GB) i les amplades de banda (GB/s, TB/s).

#### T8

- **Precedència textual (criteri general, aplicat aquí al bit `E`)**: els apunts (`Ax.qmd`) prevalen sobre els problemes (`Ex.qmd`) i solucions (`Sx.qmd`); dins dels apunts, el cos del text i els `.callout-note` prevalen sobre la resta de callouts i continguts.
- **Bit de permís d'escriptura `E`**: la teoria i els enunciats/solucions usen el bit **E** (`E = 1` → permís d'escriptura; `E = 0` → només lectura), **no `W`**. Quan un enunciat heretat usava `W` (`1` = només lectura, polaritat oposada), s'ha reescrit a `E`, aplicant el criteri de precedència textual.
- **Bit de validesa `V`**: la teoria usa **V** (*valid bit*, notació RISC-V Sv32 / Harris & Harris) per al bit de presència d'una PTE, no **P**. Els enunciats i solucions, que usaven `P` (notació x86 i dels exàmens antics d'EC), s'han reescrit a `V`, aplicant el mateix criteri de precedència textual; `#wrn-mv-notacio-v` a `A8.qmd` documenta la notació `P` per a qui consulti exàmens anteriors.
- **Mida de pàgina explícita**: si un enunciat de memòria virtual no especifica la mida de pàgina però les adreces la impliquen, s'afegeix explícitament a l'enunciat (rigor i bona definició).
- **Estat inicial del TLB**: quan es dona l'estat inicial d'un TLB completament associatiu amb LRU, cal especificar també l'**ordre d'ús** (MRU→LRU) de les entrades vàlides; sense això el reemplaçament és ambigu.
- **Canvi de mida de pàgina sobre un estat fix**: una pregunta que reutilitzi una taula de pàgines o un TLB donats per a una mida de pàgina concreta i en canviï la mida es torna incoherent; en aquests casos es reformula en clau **qualitativa** (efecte sobre el nombre de fallades).

#### T9

- **`ecall`**: la convenció de crides al sistema Linux/RISC-V usa `a7` per al codi de servei (no `a0`) i admet fins a sis arguments (`a0`–`a5`).
- **RSE**: cal salvar **tots** els registres generals sense excepció, independentment de les convencions de l'ABI.
- **`mepc`**: en excepcions, apunta a la instrucció causant; en interrupcions, a la instrucció següent. L'ajust (`mepc + 4`) és responsabilitat de la RSE, no del hardware.
- **Zicsr**: les instruccions CSR (`csrrw`, `csrrs`, `csrrc` i variants immediates) pertanyen a l'extensió Zicsr, no a RV32I base. Els callouts d'ISA s'etiqueten `## Zicsr ISA — ...`.
- **Mode S**: el tractament de fallades de TLB per programari requereix mode S (`satp`, `stval`, `sfence.vma`). El cos del text descriu el mecanisme en mode M; l'aprofundiment cobreix mode S.

### Problemari i solucionari (PE/PS)

- **Referències creuades cap a la teoria** (Nivell 2): als exercicis i solucions, afegir referències `@sec-nom` a la secció de teoria rellevant quan el concepte clau no és obvi o quan l'estudiant típicament s'encalla. No de forma mecànica a tots els exercicis, sinó selectivament. Nivell 3 (`@nte-`, `@tip-`...) admès quan la solució és aplicació directa d'un exemple concret de teoria.
  - Format recomanat als enunciats: nota al final del bloc `{#exr-}` o sota la capçalera de secció: «*Vegeu `@sec-nom`.*»
  - Format recomanat a les solucions: integrat al text de la solució on es fa servir el concepte.
- **Cobertura**: aplicar als xats de revisió de cada tema. E2/S2 es retoquen en un xat breu un cop A2.qmd tingui els slugs complets (tasca Claude Code).
- **Veu dels enunciats**: 2a persona del **plural** («Traduïu», «Calculeu», «Contesteu»; no «Tradueix», «Calcula», «Contesta»). Aplicat sistemàticament a E6 i E4.

#### Convencions globals del laboratori

- **Punt d'entrada**: `_start` (no `main`). Directiva `.globl _start` al principi del fitxer.
- **`_start` ha de ser la primera etiqueta de `.text`**: RARS inicia l'execució a la primera instrucció del segment de text, i l'opció «start at main» només reconeix l'etiqueta `main`. `_start` no ha de tenir pròleg ni epíleg, perquè no és callee de ningú i acaba amb la sortida `li a7, 93` + `ecall`; sí que ha d'usar registres segurs per a les dades pròpies que travessen crides. Aplicat a L4, L5 i L6, verificat empíricament amb RARS 1.6; pendent d'aplicar a L3.
- **Sortida del programa**: `li a7, 93` + `ecall` (syscall `exit2`). No es fa servir `startup.s`.
- **Directives de segment**: `.data` i `.text` (sense `.section`), sense indentar, a columna 0.
- **Codi dels exercicis**: integrat al `.qmd` (no hi ha fitxers `.s` separats). Els alumnes fan copy-paste.
- **Estructura de cada exercici**: enunciat en `{#exr-...}` + solució en `{#sol-...}`.
- **Lliuraments** i **Lectura prèvia**: dues seccions fixes al principi de cada sessió, en aquest ordre. "Lliuraments" porta una taula amb els exercicis i el nom del fitxer de lliurament; "Lectura prèvia" porta una taula amb columnes "Concepte" i "On trobar-ho".
- **Capçaleres de "Lliuraments" i "Lectura prèvia"**: `### ` (Heading 3), no `## `, amb `{.unnumbered}`. És un *dirty hack* per evitar que la capçalera de pàgina del PDF quedi fixada a "Lectura prèvia" (efecte que sí que es produeix amb Heading 2).
- **Nom de figura SVG**: `L<N>_nom_figura.svg` (fitxer font a `22_figs_originals/`). El pre-render genera `auto_figs/L<N>_nom_figura__original_light.svg` i `_dark` automàticament.
- **Comprovació pràctica**: les verificacions a RARS (valors esperats, ús del depurador) s'inclouen com a `{.callout-tip title="Comprovació pràctica"}` dins el bloc `{#sol-...}` corresponent. No porten etiqueta `#tip-` perquè no es referencien des d'altres punts del text.
- **Directives `.eqv`**: es defineixen **abans** de la primera directiva de segment (`.data` o `.text`), fora de qualsevol secció.

#### Nom dels fitxers de lliurament

Patró: `s<N>_<S>_<E>.<ext>` — sessió, secció, exercici, extensió (`.s` per a codi assemblador, `.md` per a documents escrits). Exemples: `s3_3_1.s`, `s3_4_2.md`, `s3_4_2.s`.

#### Ordre i atribut de seccions no numerades

Les seccions `### Lliuraments` i `### Lectura prèvia` porten `{.unnumbered}` per evitar que incrementin el comptador i provoquin un decalatge entre la numeració dels exercicis i els noms dels fitxers de lliurament. S'usa Heading 3 (no Heading 2) com a *dirty hack* per evitar que la capçalera de pàgina del PDF quedi fixada a "Lectura prèvia". L'ordre fix al principi de cada sessió és:

```markdown
### Lliuraments {.unnumbered}
### Lectura prèvia {.unnumbered}
```

## Llenguatge

### Referència normativa

- La norma general és l'**IEC** (Institut d'Estudis Catalans): [DIEC2](https://dlc.iec.cat/) i [Optimot](https://optimot.cat/).
- El català normatiu és el criteri de resolució per a qualsevol dubte lèxic o ortogràfic no cobert explícitament per aquesta guia.

### Criteris generals

- **Camel Case**:
    - Només en els sintagmes anglesos.
    - En els sintagmes catalans (títols inclosos) només la primera lletra en majúscula.
- **Després de dos punts**: minúscula en enumeracions i explicacions breus; majúscula en citacions textuals i paràgrafs independents.
- **Nombres**:
    - Les quantitats petites (una instrucció, dos bytes) o genèriques (mil, deu mil) al cos del text preferiblement amb lletres.
    - La resta en nombres: "5 V", "8 bits", "12 bits", "16 bits", "32 bits", "RV32I", `x0-x31`.
    - **Separador de milers**: espai («65 535»), no coma anglesa («65,535», ambigua amb la coma decimal catalana) ni punt.
- **Prefixos de mida binaris vs. decimals**: `KiB`, `MiB`, `GiB`, `TiB` (IEC, base 2) per a qualsevol mida que sigui una potència de 2 —mida de cau, de memòria, de pàgina, de bloc, rangs d'adreçament, etc.—, que és la immensa majoria de casos a EC. `KB`, `MB`, `GB`, `TB` (base 10) es reserven exclusivament per a mides genuïnament decimals (p. ex. la capacitat comercial anunciada d'un disc, o les referències de mercat aproximades de `A7.qmd §El problema de la diferència entre processador i memòria`, @sec-gap-memoria). Explicat a `A2.qmd` (@cau-prefixos-binaris), primera aparició al llibre; en cas de dubte, per defecte `KiB`/`MiB`/`GiB`/`TiB`.
- **Dígits hexadecimals, majúscules vs. minúscules**: la preferència és per majúscules (p. ex. `0xE6666666`), però s'admeten minúscules perquè és el criteri de RARS. No cal, doncs, unificar-ho sistemàticament allà on ja apareguin totes dues grafies.
- **Veu impersonal**: Sempre: "Cal verificar que no hi ha errors" (no "hem de verificar"). Excepcions:
    - **`{.callout-tip}`**: segona persona del singular per a instruccions directes a l'estudiant (*calcula*, *determina*, *suposa que...*). Criteri revisat el 2026-07 (revisió interna T2, xat A2-E2-S2); **no confondre amb els enunciats `#exr-`, que usen plural** (vegeu `§Problemari i solucionari`). **Excepció dins la pròpia excepció**: als exemples *narrats* (una traça o un escenari que es va desenvolupant pas a pas, no una instrucció puntual), s'admet el «nosaltres» expositiu (*Considerem un sistema amb...*, *Suposem que...*, *Sabem que...*): pràctica consolidada a T7 i T8, revisada el 2026-07 (revisió interna T8, xat A8-E8-S8). El criteri per triar entre tots dos: si la frase estableix el marc o l'estat d'un exemple, «nosaltres»; si demana una acció puntual a l'estudiant («calcula», «indica»), 2a persona del singular.
    - **Instruccions operatives pas a pas**: imperatiu en segona persona del plural (*descarregueu*, *obriu*, *executeu*).

### Puntuació

- **Punt d'acabament de frase**: Sempre. Totes les frases del cos del text, incloses les llistes de vinyetes, han d'acabar obligatòriament en punt. Excepció: les llistes de passos en notació tècnica amb fletxa (`→`) no porten punt final, ja que no constitueixen prosa sinó notació de seguiment pas a pas.
- **Negretes acabades en dos punts**: Els dos punts mai en negreta.
- **Nombres decimals**: Amb coma, no amb punt. Ex: «0,5 V», «3,14», $1{,}045$.
- **Abreviatura de *versus***: S'usa `vs.` (amb punt), que és la forma correcta en català segons l'[Optimot](https://aplicacions.llengua.gencat.cat/llc/AppJava/index.html?action=Principal&method=detall&input_cercar=versus&database=FITXES_PUB&idFont=14008). No s'usa «versus» desenvolupat excepte en prosa formal.

### Sigles, símbols i notació

- La **primera vegada** que apareixen s'han d'escriure les paraules completes seguides de la sigla entre parèntesis en majúscules. Exemple: `***Instruction Set Architecture*** (**ISA**)`.
- Cada sigla **s'ha de recollir** al **compendi de sigles** `12_sigles_simbols.qmd`.

- Sigles dels `{.callout-warning}` (aprofundiments no avaluables).
- Noms de camps individuals de registres i bits de control (p. ex. `MIE`, `MPIE`, `VPN`, `PPN`, `ASID`).

### Codi, matemàtiques i cursiva

**Regla general**: el format el determina la **naturalesa de l'element**, no el context on apareix.

- **Backtick** (`` ` ``) — **codi**: tot allò que existeix literalment en un programa, en una ISA o en un fitxer: registres (`t0`; també els CSR: `mepc`, `mstatus`…, fins i tot en títols de secció, com fa T9), instruccions (`addi`), directives (`.data`), variables i expressions C (`i`, `p++`), camps de bits (`opcode`), adreces concretes (`0x10010000`), fitxers, comandes i etiquetes.
- **LaTeX math** (`$…$`) — **matemàtiques**: quantitats, variables i expressions matemàtiques: mides genèriques ($n$ bits, $B = 2^b$), índexs de fórmules i algorismes ($q_i$), rangs ($[-2^{11}, 2^{11}-1]$), operacions ($rd = M_w[rs1 + SignExt(offset)]$). Els superíndexs numèrics s'escriuen sempre en math (`$2^{8}$`), també dins de cel·les de taula; no s'usa la sintaxi Pandoc `2^8^`.
- **Cursiva** — **llengua**: anglicismes en primera aparició (vegeu §Anglicismes) i èmfasi lleu. Mai per a codi ni per a variables matemàtiques.
- **Text pla** — la resta: nombres amb unitats («8 bits», «4 bytes»), noms d'arquitectures i extensions (RISC-V, RV32I, extensió M), tipus de format d'instrucció (S, B).

**Cas fronterer — variables d'una lletra**: si l'element viu en un programa concret (està declarat al codi de l'exemple), backtick (`i`, `p`); si viu en una fórmula o algorisme abstracte, math ($i$, $n-1$).

**Dins de les fórmules**:

- `\text{…}`: paraules catalanes, sigles i unitats ($\text{CPI}$, $t_h = 2\text{ ns}$, $\text{núm. encerts}$). És l'opció per defecte per a qualsevol camp o paraula ($\text{offset}$, $\text{índex}$).
- `\texttt{…}`: literals de codi dins d'una fórmula ($\texttt{0x100100F}$, $\texttt{vec[i]}$).

**Criteri per context**:

| Context | Backtick | Math | Cursiva |
| :--- | :---: | :---: | :---: |

**Manlleus en cursiva als títols de secció**: la cursiva als títols de secció es reserva **exclusivament** als manlleus sense equivalent català consolidat (p. ex. *loop tiling*), que es mantenen en cursiva també quan encapçalen una secció (com a la resta del text). No s'usa mai per a èmfasi ni per a cap altre motiu; per a la resta de casos, el títol es reescriu. Un cop es fixi un equivalent català per a un manlleu, el títol s'hi actualitza i deixa de dur cursiva.

#### Retalls (crops) d'una figura font única

Quan una figura "detall" o "zoom" ha de mostrar literalment un **subconjunt geomètric** d'una figura més gran ja existent (mateixes coordenades, mateix contingut, sense redibuixar ni afegir informació), es defineix com a **retall** a `24_specs/retalls.toml` en lloc de duplicar-lo com a SVG independent, evitant mantenir dues fonts sincronitzades manualment.

**Condició d'aplicabilitat**: el retall només és vàlid si és un subconjunt net del `viewBox` de la figura font — cap element ha de quedar tallat a mig camí (connectors, fletxes o etiquetes "penjant" sense l'element que assenyalaven). Si el detall necessita mostrar contingut que no hi és a la figura font (més etiquetes, més precisió, redisseny), continua calent un SVG independent a `22_figs_originals/`.

**Format de `24_specs/retalls.toml`:**

```toml
[crops.T5_exemple_detall]
source = "T5_exemple__original_light"   # sense extensió; ha d'existir a auto_figs/
title  = "Descripció del detall"         # opcional
x = 54    # min-x del retall, en coordenades del viewBox de la font
y = 60    # min-y
w = 300   # amplada
h = 250   # alçada
```

L'script `25_scripts/gen_crops.py` només reescriu `viewBox`/`width`/`height` de l'element arrel; no toca cap altre contingut. S'executa com a pas de `pre-render` **després** de `norm_font.py` (necessita la font ja normalitzada a `auto_figs/`) i **abans** de `gen_dark.py` (perquè el retall també rebi automàticament la seva variant dark).

### Referències creuades

Les referències creuades funcionen de manera diferent a HTML i a PDF. Per assegurar la compatibilitat amb les dues sortides:

- **Seccions, callouts, figures, taules, equacions**: useu sempre la sintaxi `@etiqueta` (funciona a HTML i PDF).
- **Enllaços a seccions dins del mateix fitxer**: `[text](#sec-etiqueta)` (funciona a HTML i PDF).
- ⛔ **No useu** `[@sec-etiqueta]` ni `[text](@sec-etiqueta)`: la sintaxi `@` per a seccions **només funciona a PDF**.

Exemple — fitxer `PS.qmd` amb una secció etiquetada:

```{.text filename="PS.qmd"}
# Problemes: Solucions seleccionades {#sec-problemes-solucions}
```

Referència des d'un altre fitxer:

```{.text filename="un_altre_fitxer.qmd"}
- [Solucions de problemes](#sec-problemes-solucions)   ✓ HTML i PDF
```

A més, com a criteri d'estil de redacció:

- Com més precises siguin, millor. Ordre de preferència creixent:
    - Tema → secció → subsecció → callout → figura → taula → equació.
    - `sec-tema-exemple`, `@sec-exemple`, `@fig-exemple`, `@tbl-exemple`, `@nte-exemple`.
- Article determinat:
    - **Amb**: "La" `@sec-exemple`, `@fig-exemple`, `@tbl-exemple` mostra...
    - **Sense**: "`@nte-exemple` recull..."
- **Figures i Taules**: no han d'estar necessàriament referenciades al text.
- **Direccionalitat**: les referències cap endavant (a contingut encara no presentat, sigui d'una secció posterior o d'un tema posterior) només s'admeten com a **punter explícit** («s'estudia a…», «es veurà a…», «vegeu…»), mai com a **dependència conceptual**: el text s'ha de poder seguir sense visitar la destinació. Punters cap endavant acceptats actualment:

    - T5 → T9: `fcsr` → `@nte-zicsr` (vegeu `TODO.md §T5 P8`).

### Presentació visual

- **`{style="text-align: center;"}`** centra el contingut *dins* del contenidor, però el contenidor en si ocupa tota l'amplada disponible. Amb `{#fig-}`, `{#tbl-}`, etc. no cal perquè ja centren automàticament.
    - Imatges dins callouts (**només HTML**; al PDF no té efecte).
- **`{style="width: X%; margin: auto;"}`** centra el *contenidor* com a bloc. Funciona bé per a taules i elements de bloc amb amplada definida (`width: X%`), però no té efecte si el contenidor ja ocupa el 100% de l'amplada.
    - Taules.
    - Elements de bloc.
- **Figures SVG** (`.light-content` / `.dark-content`): els blocs de figura **no** porten `style="text-align: center;"`. Les figures amb `{#fig-}` ja centren automàticament a HTML i PDF.

### Protocol de contribució

La branca `main` està **protegida**: tot canvi s'integra a través d'una **Merge Request (MR)**.

```bash
git checkout main && git pull                   # 1. Actualitzar main
git checkout -b contingut/t5-vectors           # 2. Branca nova (vegeu convenció de noms)
# ... canvis ...
git add A5.qmd
git commit -m "T5: afegeix secció sobre vectors"  # missatge: en català, present, descriptiu
git push origin contingut/t5-vectors           # 3. Pujar branca
# 4. Obrir Merge Request a GitLab apuntant a main
```

### Convenció de noms de branques

| Tipus de canvi | Format | Exemple |
| :--- | :--- | :--- |
| Contingut nou | `contingut/<tema>-<descriptor>` | `contingut/t5-vectors` |
| Correcció | `fix/<descriptor>` | `fix/t3-errada-alineacio` |
| Configuració/tooling | `config/<descriptor>` | `config/quarto-pdf-output` |
| Revisió externa | `revisio/<grup>-t<N>-t<M>` | `revisio/g2-t4-t6` |

Durant la **fase de revisió externa**, cada grup de treball manté una sola branca amb el format `revisio/<grup>-t<N>-t<M>`, on `<grup>` identifica el grup i `t<N>-t<M>` el rang de temes que revisa. La branca s'actualitza amb `main` periòdicament (`git merge main`) per evitar divergències grans, i es tanca mitjançant una Merge Request un cop completada la revisió del bloc de temes. Un cop integrada, la branca s'esborra i s'arxiva amb una etiqueta anotada `revisio-externa/<grup>-t<N>-t<M>` que reculli el commit d'integració.

La branca `main` està protegida. El nivell d'accés és el següent:

| Rol | Push directe a `main` | Merge Requests |
| :--- | :---: | :---: |

### Renderitzar el projecte

El projecte té dues sortides independents: **HTML** i **PDF**. Són pipelines completament separades — HTML usa Bootstrap, PDF usa LaTeX (`scrbook`). Cap de les dues es construeix sobre l'altra.

```bash

quarto render --to html   # ràpid, recomanat durant el desenvolupament
quarto render --to pdf    # lent (compilació LaTeX), recomanat abans de la MR
quarto render             # genera les dues sortides
```
